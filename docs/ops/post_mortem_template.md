# Post-Mortem（事故复盘）模板（P2-14）

> 用法：复制本文件为 `docs/postmortems/YYYY-MM-DD-<slug>.md` 填写。
> 触发条件（强制）：**每一次 P0 / P1 事故必须产出**（评估 §9-P2-14）。
> 时限：事故解决后 **5 个工作日内** 完成初稿并评审。
> 原则：**对事不对人（blameless）**，聚焦系统性缺陷而非个人失误。

## 2. 时间线（Timeline）

> 精确到分钟，标注 **MTTD / MTTA / MTTR**（对齐评估打分口径）。

| 时刻(UTC) | 事件 | 证据（日志/指标/命令输出） |
|---|---|---|
| T+0 | 故障开始（最早可观测异常） | |
| T+a | 告警触发 / 被发现 | MTTD = a |
| T+b | 值班首响（开始处置） | MTTA = b-a |
| T+c | 采取关键缓解动作 | |
| T+d | 服务恢复 | MTTR = d-a |

## 3. 根因分析（Root Cause）

- **直接原因**：
- **根本原因**（连问 5 Why，到系统性/流程性为止）：
- **为什么没被更早发现**（监控盲区？阈值？runbook？）：
- **为什么没被自动缓解**（缺过载保护？缺回滚？门禁被绕过？）：

> 常见分类参考：代码缺陷 / 配置漂移（→ P0-1 checker）/ 容量不足（→ P1-9 基线）/

## 4. 检测与响应评估

- 告警是否在 MTTD 目标内触发？漏报/误报？

- runbook 步骤是否可执行？有无过时命令？（→ 立即修 runbook）
